# 구현 문서

- 문서는 현재 코드·마이그레이션·테스트로 확인한 사실을 쓴다. 목업·계획·로컬 동작·운영 반영을 명확히 구분한다.
- 아키텍처는 `architecture.md`, 실제 스키마는 `erd.md`, 흐름/계약은 `data-flows.md`와 기능별 문서에 둔다. 같은 긴 설명을 여러 파일에 복제하기보다 연결한다.
- 오래된 설명을 그대로 규칙화하지 않는다. 예를 들어 지역 좌표와 실제 공연장 좌표, 과거 스키마 버전/테이블 개수는 최신 코드로 검증한다.
- DB 관계는 실제 FK와 단순 ID 참조를 구분한다. 클라이언트 AsyncStorage/메모리 모델을 PostgreSQL 테이블로 그리지 않는다.
- API·라이선스·배포 정책은 확인한 공식 출처와 확인 범위를 남긴다. 무료/비상업이라는 이유만으로 모든 이미지·스크래핑이 허용된다고 단정하지 않는다.
- 명령에는 실행 폴더·환경 조건을 명시하고 비밀값 대신 placeholder를 쓴다. 개인 Mac 절대 경로·인증 URL·토큰을 문서에 넣지 않는다.
- 검증 결과에는 실제 실행한 것과 생략/조건부 테스트를 구분한다. 빌드 완료를 실기기 실행 성공이나 운영 배포 완료로 표현하지 않는다.
- 이번 작업에 관련된 부분만 갱신하고 기존 문서 전체를 불필요하게 재작성하지 않는다.
- AGENTS.md에는 작업 제약만 둔다. 구현 현황·의사결정 이유·검증 이력은 해당 문서에 기록하고, 지침 정리 기준은 `agent-instructions.md`를 따른다. 일상적인 기능 추가마다 모든 지침을 늘리지 않는다.

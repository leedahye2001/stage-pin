# 운영 로그인·굿즈 저장 배포 검증

기준일: 2026-11-05 (Asia/Seoul). 코드·CI·운영 반영·실제 사용자 흐름을 구분한다. 인증 코드·쿠키·키·회원 개인정보는 이 문서에 남기지 않는다.

## 1. 운영 로그인

- 운영 MY에서 카카오 로그인 → 고정 callback → 로그인 완료 안내/프로필 표시를 확인했다.
- 새로고침 뒤 MY를 다시 열었을 때 로그인 유지, 로그아웃 후 로그인 버튼 표시, 새 탭에서 로그아웃 상태 유지, 카카오 재로그인 성공을 확인했다.
- 기존 배포본은 MY에서 새로고침 후 홈으로 돌아가는 경우가 있었다. 세션은 유지됐으며, 새 배포의 직접 URL 진입도 별도로 확인한다.
- 동일 브라우저에서 `/api/v1/auth/me` 직접 열기는 브라우저 도구가 차단했다. 이 경로로 로그아웃 직후 HTTP 상태를 확인했다고 주장하지 않는다. API의 인증/로그아웃/401 연결은 별도 DB 통합 테스트가 검증한다.

## 2. 변경 반영·검사·배포

- 반영 대상: 폴더별 AGENTS 지침, Expo SDK 패치 정렬, 회원 소유 굿즈/사진 저장, 공개 탐색형 홈, 인증 성공·실패 DB 테스트.
- CI backend에 별도 인증·굿즈 PostgreSQL 서비스를 두어 두 DB 조건부 테스트를 실행한다. 실제 외부 API·운영 키는 CI에서 사용하지 않는다.
- 로컬 프런트 lint/TypeScript/Node 테스트 54개 통과.
- 로컬 macOS expo-doctor는 20개 중 19개 통과, CocoaPods 도구 검사 실패. 웹 배포 검사와 iPhone 네이티브 빌드 성공을 혼동하지 않는다.
- 서버 83개 중 82개 통과, 외부 AI 실호출 조건부 테스트 1개 미실행. 인증 DB 7개/굿즈 DB 4개는 새 PostgreSQL에서 `--rerun-tasks`로 실행했다.
- 웹 export 통과. PR #13의 backend/mobile CI 2개 성공을 확인한 뒤 main에 병합했다(merge `1372ad4`). 기능 PR·운영 배포 커밋은 확인 후 추가한다.
- PR #14의 HEAD `c8cd253` backend/mobile CI 성공 후 main에 병합했다(merge `e9ebfa2`). Vercel 배포 `85MhvaeX5LyFytL2mm3Lh93LCUik` Ready, Render 배포 `dep-dbm433l9fdbs73bppnqg` 서비스 live 및 Flyway V8 적용을 확인했다. 둘 다 `e9ebfa2` 기준이다.
- 운영 회귀 발견: Render의 `/api/v1/goods` GET은 200, `/api/v1/goods/` GET은 403. Vercel collection wildcard rewrite도 403이었다. 내 글/인증 프록시는 비로그인 401로 정상이다. collection의 빈 wildcard 끝 슬래시를 방지하는 exact rewrite를 추가하고 회귀 테스트를 둔다. 보안 허용 경로를 넓혀 해결하지 않는다.

## 3. 운영 굿즈 등록 검증

아직 실행 전. 최신 프런트·백엔드 반영 후 진행한다.

1. 실제 카카오 세션으로 개인정보 없는 검증용 이미지, 숫자 가격, 상태 코드를 등록한다.
2. 글은 검증용·거래 불가임을 명시한다. 실제 상품 판매·거래 신청은 하지 않는다.
3. 목록/상세/MY에서 동일 글과 사진·가격·상태가 나타나는지 확인한다.
4. 새로고침/상세 URL 재진입/로그아웃·재로그인 후 유지되는지 확인한다.
5. 비로그인 공개 조회와 등록·내 글 접근 제한을 구분한다.

수정/삭제 API는 이번 범위에 없으므로 검증 글의 제거를 임의 DB 삭제로 처리하지 않는다. 테스트 글을 남겼다면 식별 가능한 비밀이 아닌 공개 글 ID와 정리 필요 여부를 기록한다.

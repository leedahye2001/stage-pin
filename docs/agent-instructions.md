# AGENTS.md 정리 기준과 변경 기록

## 목적

2026-11-06: 프로젝트 설명서와 작업 제약을 분리했다. AGENTS.md에는 코드에서 의도를 알아내기 어렵거나 잘못 변경했을 때 보안·데이터·호환성 문제가 생기는 규칙을 남긴다. 파일 개수나 줄 수 자체를 성과로 삼지 않는다.

## 배치 기준

| 위치 | 남길 내용 | 다른 곳에서 확인할 내용 |
| --- | --- | --- |
| 루트 AGENTS.md | 공통 승인 범위, 데이터 경계, Git·검증·비밀정보 보호 | 전체 폴더 목록, 기술 스택, 작업 일지 |
| mobile/backend | 플랫폼 경계, 실제 실행상 함정, 대표 검증 명령 | 버전 목록, 프레임워크 튜토리얼 |
| 도메인·세부 폴더 | 인증, 소유권, 사진 검증, 좌표, 라이선스 등 고유 제약 | 상위 규칙의 반복 |
| 구현 문서 | 아키텍처, 선택 이유, 현재 구현 범위, 실행 절차 | 에이전트 행동을 지시하는 공통 규칙 |
| 날짜가 있는 검증 기록 | 실행 환경·소스 커밋·실행 결과·미검증 범위 | 앞으로도 같은 설정이라는 가정 |

루트부터 작업 경로에 해당하는 지침만 읽는다. 관련 API·설정·테스트까지 수정 범위가 넓어지면 그 경로의 지침도 추가로 읽는다. 모든 하위 파일이 자동 로드된다고 가정하거나 전체 지침을 항상 읽게 하지 않는다.

## 이번 변경과 이유

- 루트의 폴더 색인을 제거했다. 새 도메인이 생길 때 색인이 누락되는 문제를 없애고 경로별 지침 확인 규칙으로 대체했다.
- 모바일의 일반 Expo/Router 설명, Bun 분기, EAS 일괄 권장을 제거했다. npm lockfile·현재 SDK 문서·기존 빌드 스크립트를 기준으로 판단한다. 웹 배포와 네이티브 설치본의 갱신은 여전히 별개다.
- 도구 버전을 여러 지침에 반복하지 않고 build.gradle, package.json, CI 설정에서 확인하도록 했다. 로컬 JDK가 없는 환경의 구체적인 Docker 대안은 실행에 필요하므로 남겼다.
- 인증/굿즈/마이그레이션/이미지 라이선스 지침은 유지했다. 짧게 만들기 위해 보안·권한·개인정보 보호를 삭제하지 않았다. 고유한 역할이 있는 하위 지침도 합치지 않았다.
- Vercel collection exact rewrite와 DB 테스트의 강제 재실행 조건을 추가했다. 추상적인 주의사항 대신 실제 장애와 확인 방법을 연결한다.
- 구현 상태는 기존 `goods-persistence.md`, 기술 선택은 `auth-goods-technical-decisions.md`, 운영 반영 이력은 `release-verification-2026-11-05.md`로 연결한다. 현재 설정은 배포 서비스에서 다시 확인해야 한다.

### 실제 회귀와 연결된 검증

1. 프록시: `/api/v1/goods` exact rewrite → 하위 경로 wildcard → SPA fallback 순서를 `mobile/tests/vercel-rewrites.test.mjs`에서 검사한다. 이 테스트는 rewrite 설정을 검사하며 실제 호스팅 동작을 대체하지 않는다. 인증·CORS 완화는 해결책이 아니다.
2. DB: 테스트 클래스의 `AUTH_TEST_JDBC_URL`/`GOODS_TEST_JDBC_URL` 실행 조건과 전용 DB를 확인한다. 환경 변수 변경 뒤 `backend/`에서 `./gradlew test --rerun-tasks --no-daemon`을 실행하고 XML 보고서의 실행/skip을 구분한다. 운영 DB는 사용하지 않는다.
3. 배포: main 병합 여부만으로 성공을 선언하지 않는다. 서비스의 실제 배포 소스·Git 연결·자동 배포 설정과 health/API/화면을 따로 확인한다.

## 유지보수 방식

- 새 규칙은 방지할 구체적 실패, 적용 경로, 확인 방법이 있을 때 추가한다. 일반적인 개발 상식이나 코드 목록은 넣지 않는다.
- 버전·구조·구현 범위가 바뀌면 해당 설정과 구현 문서를 수정한다. 지침은 제약이나 실행 조건이 바뀔 때만 수정한다.
- 규칙으로 막던 문제가 테스트·설정으로 완전히 강제되면 중복 경고를 줄인다. 보안 정책·사용자 결정은 구현에서 자동 발견 가능하다는 이유만으로 폐기하지 않는다.
- 프레임워크 예제의 명령이나 글의 수치를 그대로 적용하지 않는다. 효과는 대표 작업에서 불필요한 탐색, 지침 누락, 회귀 여부로 판단하며 토큰·시간 절감률은 측정 없이 주장하지 않는다.

## 이번 작업의 검증 범위

문서만 수정했다. 경로·대표 명령을 실제 파일/스크립트와 대조했다. `git diff --check` 통과, `mobile/`에서 `node --test tests/vercel-rewrites.test.mjs` 1개 통과·실패/skip 0개를 확인했다. 전체 앱 lint/타입 검사/빌드, 서버 테스트, 실기기 실행, 운영 배포는 이번 문서 변경으로 재실행하지 않았다. 기존 운영 검증 결과를 이번 작업의 실행 결과로 재사용하지 않았다.

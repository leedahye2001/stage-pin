# 하단 탭 구현 범위

- 공통 진입점: `mobile/src/app/(tabs)/_layout.tsx` → `AppTabs`.
- iOS: Metro가 `AppTabs.ios.tsx`를 선택한다. Expo Router 58의 `NativeTabs`로 UIKit 시스템 탭바를 사용한다. 공연장·일정·홈·굿즈·MY 순서이며 최초 진입은 가운데 홈이다.
- 웹·Android: `AppTabs.tsx`의 JS 탭바. 같은 순서의 다섯 버튼을 같은 너비로 배치하고 외곽 패딩은 4, 버튼 별 마진·패딩은 0으로 통일한다. 바 높이는 64, 최대 너비는 390이다.
- 공연장 화면은 `src/app/(tabs)/explore.tsx`에 있으며 `/explore` URL과 기존 검색·지도 기능을 유지한다. 홈 검색창 아래의 중복 지도 진입 링크는 제거했다.

## iOS에서 시스템이 담당하는 부분

iOS 26의 Liquid Glass, 선택 표시와 터치 추적, 시스템 탭 항목 내부 간격은 UIKit이 담당한다. `GlassView`를 배경에 놓는 것과 네이티브 탭 컨트롤을 사용하는 것은 다르다. 무지갯빛 반사의 색·위치나 눌림 형태를 앱에서 고정하거나, 참고 이미지와 픽셀 단위로 같게 만드는 것은 보장하지 않는다. 시스템 탭바의 너비·내부 패딩은 현재 공개 Expo API로 임의 조절하지 않는다. 이전 iOS에서는 해당 OS의 시스템 탭바가 표시된다.

웹·Android의 블러/반사선은 시각적 대체 효과다. iOS의 길게 누른 채 이동하는 시스템 선택 효과를 구현했다고 주장하지 않는다.

## 수동 실기기 검증

1. 공연장·일정·홈·굿즈·MY 순서와 각 화면/선택 상태, 앱 최초 진입 시 홈 선택 확인.
2. 선택 항목을 누른 채 옆 항목으로 천천히 움직이고 놓아서 네이티브 선택 표시, 굴절, 최종 이동 화면 확인.
3. 각 화면 맨 아래까지 스크롤하여 마지막 콘텐츠에 접근되는지 확인. iOS의 자동 ScrollView 콘텐츠 인셋을 사용하며 굿즈 등록 FAB는 시스템 바 위에 배치한다.
4. 홈 인디케이터 여백과 시스템 접근성 설정에 따른 유리 효과 차이 확인.

빌드·설치·프로세스 실행 성공만으로 2번의 시각적 동작 검증을 대체할 수 없다.

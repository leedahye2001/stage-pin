# StagePin — 팬의 무대와 굿즈를 연결하는 로드맵

## 제품 방향

아이돌 중심의 팬 활동 서비스. 솔로·밴드도 배제하지 않는다.
관심 아티스트 → 예매 일정 → 공연 현장 교환/굿즈 판매 → 로그북으로 연결한다.
첫 거래 범위는 개인 간 굿즈 교환·판매이며 티켓 매매, 공동구매, 판매자 정산은 제외한다.

## 1. 목업 검증 — 현재 구현 범위

- 하단 탭: 홈 / 일정 / 굿즈 / MY. 공연 탐색과 굿즈 교환·판매에 집중하기 위해 로그북 탭과 홈 진입 배너는 숨긴다. 기존 로그북 화면과 데이터는 보존한다.
- 홈: 상단 고정 검색, 배너 캐러셀, 실제 아티스트 사진·찜, 찜한 가수의 검수된 예매 일정, 현장 교환, 판매 굿즈.
- 굿즈: 아티스트·교환/판매 필터, 키워드 검색, 찜, 상세, 신청 미리보기.
- MY: 이번 실행에서 찜한 굿즈와 데모 신청 내역.
- 기존 KOPIS 공연 탐색은 `/explore`에 유지. 목업에 실제 공연 데이터를 섞지 않음.
- 굿즈·상품 일러스트·닉네임·일정 탭의 샘플 일정·가격은 화면 검증용. 공식 판매/인증/실제 일정이 아님.
- 홈 프로필은 MusicBrainz/Wikidata/Commons 공개 API, 홈 예매 일정은 출처 확인 자료를 사용하며 굿즈 목업과 구분. 사진 이용 기준은 `artist-profile-sources.md` 참고.
- 찜과 신청은 메모리에만 보관하며 앱 재시작/웹 새로고침 시 초기화.
- 데모 신청은 서버로 전송되지 않으며 실제 채팅·예약·결제·배송은 없음.

완료 기준: 백엔드 없이 홈 → 필터/검색 → 상세 → 데모 신청 → MY 탐색 가능, 빈 결과 및 없는 상품 처리.

## 2. 교환·판매 게시 MVP

- 로그인, 프로필, 관심 아티스트. 굿즈/등록 글과 거래 신청을 별도 모델로 관리.
- 사진 업로드, 아티스트/멤버/굿즈 종류, 상태·하자 설명, 수정/삭제.
- 교환 글: 보유·희망 굿즈. 판매 글: 가격·수량·배송비. 현장/택배 거래 방식.
- 현장 거래는 공연·회차와 연결. 정확한 만남 장소와 연락처는 공개 글에 노출하지 않음.
- 작성자 권한, 입력 검증, 이미지 파일 크기·형식 검증, 페이지네이션.

완료 기준: 다른 계정이 작성자 글을 수정할 수 없고, 삭제된 글에 신청할 수 없음.

## 3. 거래 MVP

- 신청 → 수락/거절 → 예약 → 양측 완료 확인 → 완료. 취소 및 분쟁 상태 별도 관리.
- 단일 굿즈 중복 수락 방지: DB 트랜잭션·유일 제약/락·멱등성 검증.
- 거래별 채팅·알림, 신고·차단, 관리자 검수. 신고 처리와 거래 상태 이력 보관.
- 실제 유저 신뢰도·후기는 완료한 거래와 연결. 목업의 가짜 인증/후기를 실서비스로 이관하지 않음.

완료 기준: 같은 물건의 동시 수락 테스트에서 한 거래만 성립. 차단한 상대의 새 신청 방지.

## 4. 판매 주문·테스트 결제

- 게시글 거래와 별도로 주문, 주문 상품, 재고 확보, 결제, 환불 모델 구현.
- 테스트 결제 → 서버 검증/웹훅 → 주문 확정. 중복 웹훅과 금액 위변조 방어.
- 실패·시간 만료·취소 시 재고 복구, 배송 상태 및 취소·환불 내역.
- PG/운영 정책 검토 전 실제 결제·계좌 송금·안전결제라는 표현은 사용하지 않음.

완료 기준: 마지막 재고 동시 주문, 결제 재시도, 중복 웹훅, 결제 성공 후 응답 유실, 취소/환불 회귀 테스트.

## 5. 운영·포트폴리오 정리

- Spring/PostgreSQL/Docker 구성 및 CI 유지. API 명세·ERD·거래 상태 전이·의사결정 기록.
- 실제로 측정한 동시성/성능 테스트와 로그·지표·오류 추적. 가상 티켓팅 10만 명 UI와 실제 서버 부하 테스트를 구분.
- AI는 이후 등록 글 태그 제안·검색 보조로 한정. 신뢰도 측정 및 사람이 수정할 수 있는 흐름 확보.
- 배포 전 개인정보 처리, 이미지/상품 권리, 미성년자 이용, 거래 분쟁·금지 품목 운영 정책 검토.

다음 작업 우선순위: 목업 피드백 확정 → 로그인/게시글 DB/API → 신청·중복 수락 방지 → 채팅/신고 → 테스트 결제.

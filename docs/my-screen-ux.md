# MY 화면 구성·기술 결정

2026-11-06 현재 구현. 사용자의 최종 요청에 따라 필터로 목록을 전환하던 구조를 없애고, 한 페이지에 모든 목록을 세로로 표시한다.

## 구성

1. MY 제목과 프로필: 닉네임, 제공된 이메일, 로그아웃. 재연동 버튼과 반복적인 저장 위치 설명은 없다. 비로그인에는 기존 공식 카카오 버튼을 표시한다.
2. 찜한 공연 → 관심 아티스트 → 내 등록 굿즈 → 찜한 굿즈 순서의 고정 세로 섹션. 분류 선택 버튼 없이 모두 같은 페이지에 나타난다.
3. 항목은 이미지 왼쪽·정보 오른쪽의 세로 목록이다. 공연/굿즈는 기존 ConcertCard/GoodsCard의 compact 옵션을 사용해 원래 홈 카드 디자인을 바꾸지 않는다. 아티스트도 사진·이름·하트가 있는 세로 행으로 표시하며 사진 크레딧 접근을 유지한다.
4. 기기 찜 가져오기는 메뉴·확인창·클라이언트 연결·서버 import API까지 제거했다. 기존 기기 찜과 회원 찜 데이터는 삭제하거나 자동 병합하지 않는다.
5. 관리자 공지 검수는 하단의 작은 보조 메뉴로 유지한다.

## 상태와 반응형

- 홈과 같은 흰 배경·중립 회색 버튼·제목 크기를 사용한다. 모바일 패딩은 marketStyles의 20px, 큰 화면은 reading 레이아웃 32px/최대 960px를 사용한다. MY는 넓은 화면에서도 읽기 쉬운 한 열 목록으로 유지한다.
- 각 섹션이 독립적으로 로딩·실패·로그인 필요·빈 목록·콘텐츠를 표시한다. 한 요청 실패로 다른 목록을 숨기지 않는다. 빈 상태는 반복된 큰 박스 대신 짧은 한 줄과 관련 이동 버튼을 제공한다.
- collectionViewState로 상태를 구분한다. 배경 재조회 실패 시 이미 받은 데이터는 유지하고 재시도할 수 있다.
- LoadingSkeleton의 list 옵션은 왼쪽 사진과 오른쪽 텍스트의 실제 행 크기를 따른다. 공연 78×108, 굿즈 78×90, 아티스트 66×66이며 계정 스켈레톤은 기존 56px 프로필에 맞춘다. 다른 화면의 기본 카드 스켈레톤은 그대로다.
- 내 등록 굿즈는 로그인 확인 후 바로 조회한다. 필터 선택 조건은 없고 기존 infinite query의 더 보기를 유지한다.
- 로그인/세션/공연 상태 배지/상세 이동/하트 동작과 사진 라이선스 정보를 보존한다. 내 일정과 굿즈 찜의 저장 범위는 변경하지 않는다.

## 검증 원칙

- 단위 테스트: 네 섹션의 순서·스켈레톤 종류, 인증/오류/빈 상태 분리, 재조회 중 기존 데이터 유지.
- 웹 UI: 하나의 화면에 네 제목이 동시에 존재하고 가로 전환 필터·가져오기 메뉴가 없음을 확인한다. 로그인·하트·등록 글은 화면 검증 때문에 변경하지 않는다.
- 서버: import 컨트롤러 매핑이 제거돼 단독 컨트롤러 테스트에서는 404다. 실제 로컬 서버는 기존 미매핑 오류 경로의 보안 처리로 403을 반환하며 가져오기를 실행하지 않는다. 단건 저장·회원 분리·quota 롤백은 계속 검사한다.
- 웹 검증과 iPhone 실기기·운영 반영은 구분한다. 이번 요청의 push는 작업 브랜치에만 수행하며 main 병합·배포는 별도다.

초기 62개 클라이언트 테스트와 필터/확인창 검증 기록은 이전 커밋의 구현에 해당한다. 현재 상태는 이 문서와 새 검증 결과를 기준으로 한다.

세로 목록 변경 검증: 클라이언트 lint·tsc·62개 테스트·웹 빌드 통과. 새 임시 PostgreSQL에서 서버 92개 중 91개 통과, 외부 모델 실호출 1개 미실행. 인증/굿즈/찜 DB 테스트는 모두 실제 실행했다. 기존 DB와 기기 저장값을 삭제하지 않고 로컬 API만 재빌드했다.

8081 MY 새로고침 후 네 제목이 동시에 DOM에 있고 가져오기 메뉴/분류 필터가 없음을 확인했다. 기존 공연 찜 2개·관심 아티스트 2개는 변경하지 않았다. 현재 브라우저 폭 649px에서 문서 가로 넘침은 없었다. 실제 iPhone 실행과 운영 배포는 검증 범위에 포함하지 않았다.

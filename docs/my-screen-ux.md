# MY 화면 구성·기술 결정

2026-11-06 현재 구현. 사용자의 최종 요청에 따라 필터로 목록을 전환하던 구조를 없애고, 한 페이지에 모든 목록을 세로로 표시한다.

## 구성

1. MY 제목과 프로필: 닉네임, 제공된 이메일, 로그아웃. 재연동 버튼과 반복적인 저장 위치 설명은 없다. 비로그인에는 기존 공식 카카오 버튼과 “로그인하면 내가 등록한 굿즈를 확인할 수 있어요.” 안내를 표시한다.
2. 로그인한 회원에게만 찜한 공연 → 관심 아티스트 → 내 등록 굿즈 → 찜한 굿즈 순서의 고정 세로 섹션을 표시한다. 비로그인·인증 확인 중·인증 조회 실패 시 제목/개수/기기 찜을 포함한 개인 목록 전체를 숨기고 MemberLoginCard에서 로그인·로딩·오류를 처리한다. 분류 선택 버튼은 없다.
3. 항목은 이미지 왼쪽·정보 오른쪽의 세로 목록이다. 공연/굿즈는 기존 ConcertCard/GoodsCard의 compact 옵션을 사용해 원래 홈 카드 디자인을 바꾸지 않는다. 아티스트도 사진·이름·하트가 있는 세로 행으로 표시하며 사진 크레딧 접근을 유지한다.
4. 기기 찜 가져오기는 메뉴·확인창·클라이언트 연결·서버 import API까지 제거했다. 기존 기기 찜과 회원 찜 데이터는 삭제하거나 자동 병합하지 않는다.
5. 관리자 공지 검수 진입 메뉴는 MY에서 제거했다. `/admin/notices` 페이지와 서버 검수 API는 삭제하지 않았다.

## 상태와 반응형

- 홈과 같은 흰 배경·중립 회색 버튼·제목 크기를 사용한다. 모바일 패딩은 marketStyles의 20px, 큰 화면은 reading 레이아웃 32px/최대 960px를 사용한다. MY는 넓은 화면에서도 읽기 쉬운 한 열 목록으로 유지한다.
- 인증 성공 후 각 섹션이 독립적으로 로딩·실패·빈 목록·콘텐츠를 표시한다. 개별 목록 요청 실패로 다른 목록을 숨기지 않는다. 인증 자체가 실패하면 개인 목록을 숨긴다. 빈 상태는 반복된 큰 박스 대신 짧은 한 줄과 관련 이동 버튼을 제공한다.
- collectionViewState로 상태를 구분한다. 배경 재조회 실패 시 이미 받은 데이터는 유지하고 재시도할 수 있다.
- LoadingSkeleton의 list 옵션은 왼쪽 사진과 오른쪽 텍스트의 실제 행 크기를 따른다. 공연 78×108, 굿즈 78×90, 아티스트 66×66이며 계정 스켈레톤은 기존 56px 프로필에 맞춘다. 다른 화면의 기본 카드 스켈레톤은 그대로다.
- 내 등록 굿즈는 로그인 확인 후 바로 조회한다. 필터 선택 조건은 없고 기존 infinite query의 더 보기를 유지한다.
- 로그인/세션/공연 상태 배지/상세 이동/하트 동작과 사진 라이선스 정보를 보존한다. 내 일정과 굿즈 찜의 저장 범위는 변경하지 않는다.

## 검증 원칙

- 단위 테스트: 네 섹션의 순서·스켈레톤 종류, 인증/오류/빈 상태 분리, 재조회 중 기존 데이터 유지.
- 웹 UI: 하나의 화면에 네 제목이 동시에 존재하고 가로 전환 필터·가져오기 메뉴가 없음을 확인한다. 로그인·하트·등록 글은 화면 검증 때문에 변경하지 않는다.
- 서버: import 컨트롤러 매핑이 제거돼 단독 컨트롤러 테스트에서는 404다. 실제 로컬 서버는 기존 미매핑 오류 경로의 보안 처리로 403을 반환하며 가져오기를 실행하지 않는다. 단건 저장·회원 분리·quota 롤백은 계속 검사한다.
- 웹 검증과 iPhone 실기기·운영 반영은 구분한다. Git 완료 절차는 루트 AGENTS.md를 따른다.

초기 62개 클라이언트 테스트와 필터/확인창 검증 기록은 이전 커밋의 구현에 해당한다. 현재 상태는 이 문서와 새 검증 결과를 기준으로 한다.

세로 목록 변경 검증: 클라이언트 lint·tsc·62개 테스트·웹 빌드 통과. 새 임시 PostgreSQL에서 서버 92개 중 91개 통과, 외부 모델 실호출 1개 미실행. 인증/굿즈/찜 DB 테스트는 모두 실제 실행했다. 기존 DB와 기기 저장값을 삭제하지 않고 로컬 API만 재빌드했다.

8081 MY 새로고침 후 네 제목이 동시에 DOM에 있고 가져오기 메뉴/분류 필터가 없음을 확인했다. 기존 공연 찜 2개·관심 아티스트 2개는 변경하지 않았다. 현재 브라우저 폭 649px에서 문서 가로 넘침은 없었다. 실제 iPhone 실행과 운영 배포는 검증 범위에 포함하지 않았다.

2026-11-10 비로그인 표시 수정: memberCollections에서 인증된 회원 여부를 먼저 검사해 비로그인·인증 실패 시 모든 개인 섹션을 숨긴다. 기기/계정 찜 데이터는 삭제하지 않는다. 8081의 비로그인 MY에서 로그인 버튼만 남고 네 개인 섹션이 없는 것을 확인했다. lint·타입 검사·클라이언트 64개 테스트·웹 빌드·diff 검사는 통과했다. Expo doctor는 20개 중 19개 통과, 로컬 CocoaPods 버전 확인 실패 1개로 종료했다(PATH에서 pod를 찾지 못함). 필수 검사 전체 성공 조건을 충족하지 못해 push·PR·main 병합은 진행하지 않았다. 서버 코드는 변경하지 않았으며 서버 재검증과 iPhone 실기기 검증은 수행하지 않았다.

같은 날 CocoaPods 복구 후 재검증: 기존 1.16.2 설치는 있었으나 PATH 누락과 ActiveSupport의 Logger 로딩 오류가 함께 있었다. 사용자 전용 실행 경로에 Ruby logger를 선로딩하는 pod 실행 파일을 추가하고 로그인 셸 PATH를 연결했다. 시스템 Ruby·프로젝트 Podfile/lockfile·의존성 버전은 변경하지 않았다. CocoaPods 1.16.2 실행, Expo doctor 20/20, lint·타입 검사·클라이언트 64개 테스트·웹 빌드가 모두 성공했다. 관리자 공지 검수 메뉴도 MY에서 제거했고 8081 화면에서 확인했다. 실제 iPhone 재빌드는 수행하지 않았다. PR의 최신 CI 및 main 반영은 별도로 확인한다.

후속 UX 수정: 비로그인 하트 입력은 공통 favoriteWriteOwner 검사로 MY에 보낸다. 공연과 아티스트는 기존 서버 저장 계약을 유지하고 굿즈 찜은 회원 ID를 가진 메모리 상태로 한정했다. MY 전용 guestMessage prop으로 기존 안내만 복원해 굿즈 등록 화면의 로그인 문구는 바꾸지 않았다. 굿즈 상세는 태블릿 이상에서 최대 1200px 본문에 정렬된 44px 뒤로가기 버튼과 24px 화면 제목을 사용한다. 데스크톱 상품 제목은 30px, 가격은 32px, 설명은 16px로 조정하고 행동 버튼을 상품 정보 열 안에 배치했다. 모바일 기본 헤더와 하단 행동 바는 유지한다.

후속 검증: lint, 타입 검사, 클라이언트 65개 테스트, 웹 빌드, Expo doctor 20/20이 성공했다. 8081에서 비로그인 공연 하트 입력 후 MY 안내로 이동했다. 로컬 굿즈 데이터가 없어 별도 임시 127.0.0.1 미리보기에서 운영 공개 글만 익명 GET으로 읽었다. 인증 정보 전달과 쓰기 요청을 차단했으며 검증을 위해 게시글을 생성하지 않았다. 이 미리보기에서 굿즈 하트의 로그인 이동과 1280px, 393px 화면의 가로 넘침 없음을 확인했다. 미리보기의 인증은 비로그인으로 고정했고 실제 카카오 로그인 재인증, 회원 간 전환, iPhone 실행은 이번에 재검증하지 않았다. 서버 계약이나 저장 스키마는 변경하지 않았다.

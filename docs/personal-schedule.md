# 내 덕질 일정 — 현재 구현

## 사용자 흐름

1. 공연 탐색 → 공연 상세 → `내 일정에 담기`에서 필요한 항목 선택.
2. 공연 기간 시작일과 해당 공연에 연결되는 확인된 선예매·일반예매 일정만 제공.
3. 저장 완료 후 해당 날짜의 일정 탭으로 이동.
4. 달력 날짜·전체/예매/공연 필터로 저장한 일정 확인. 예매처·공연 상세·출처 링크로 이동.
5. 사용자가 공연 카드의 `관람 예정`을 직접 표시. 저장만으로 예매 완료가 되지 않음.
6. `빼기` → 확인 후 내 달력에서 제거. 공연 찜·실제 예매에는 영향 없음.

아티스트 찜은 달력에 자동 추가하지 않는다. 확인된 관련 예매일을 별도 추천하고 사용자가 담는다.
현장 거래 일정은 실제 거래 확정 기능이 없어 아직 추가하지 않는다.

## 데이터 신뢰도와 날짜

- KOPIS는 정확한 개별 회차 정보가 아닌 기간 날짜를 제공하므로 시작일로 저장하고 시각은 표시하지 않는다.
- 공연 기간 종료일을 함께 보관·표시하지만 해당 기간 매일 공연한다고 가정해 일정을 복제하지 않는다.
- 정확한 관람일·회차는 공식 예매처에서 확인해야 한다. 이번 버전은 개인 회차별 날짜 편집을 지원하지 않는다.
- 예매 일정은 `ticket_opening` 중 검증 시각·날짜·출처·예매 링크가 있는 선예매/일반예매만 사용.
- 상세 연결은 공연 ID가 같거나, ID가 없는 일정의 정규화 제목과 아티스트가 모두 일치할 때만 한다. 아티스트명만으로 다른 공연 일정을 붙이지 않는다.
- 달력·시간 표시는 `Asia/Seoul`. 날짜 선택·윤년·월 전환을 별도 순수 함수로 검사한다.
- 저장은 스냅샷이다. 일정 변경·취소 자동 동기화와 푸시 알림은 미구현이며 출처 확인이 필요하다.

## 저장 범위

`SavedSchedulesProvider` → AsyncStorage `stagepin:saved-schedules:v1`.
서버 DB/API·사용자 계정·기기 간 동기화는 추가하지 않았다. 브라우저 저장소 삭제나 기기 변경 시 복원할 수 없다.
사진·연락처·주문 정보는 저장하지 않는다.

- 로딩 전 수정 금지. 읽기 실패 시 빈 배열을 저장해 기존 데이터를 덮어쓰지 않음.
- 변경은 순차 처리하고 디스크 저장 성공 후 화면 상태를 갱신. 실패 시 기존 목록 유지.
- 같은 일정 ID는 중복 등록하지 않으며 기존 수동 관람 상태를 보존.
- 형식이 잘못된 저장 데이터는 오류 안내 후 그대로 유지.
- 등록·삭제·관람 상태, 기기 저장 실패와 외부 API 조회 실패를 별도로 안내.

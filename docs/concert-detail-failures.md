# 공연 상세 실패와 예매처 미제공 구분

## 수정 원인

`KopisConcertClient.findById`가 상세/시설 조회 실패 시 검색 목록의 요약 객체를 200 정상 응답으로 반환했다. 요약 객체의 `ticketLinks`는 항상 빈 목록이므로 프론트는 실패를 예매처 미등록으로 오인하고 정상 상세 캐시에 저장했다. PF289772(DAY6 부산)은 KOPIS에 놀유니버스 상품 26005357 링크가 등록되어 있다.

## 동작

- 상세 또는 시설 조회 실패는 502와 안전한 오류 메시지를 반환한다. 요약 데이터로 성공을 대체하지 않는다. 로그에도 키가 포함될 수 있는 외부 요청 예외 메시지/스택을 남기지 않는다.
- 검색 캐시 접근과 상세 조회는 같은 모니터로 동기화한다. 캐시 순회 중 검색 결과가 바뀌는 경쟁을 막고 외부 상세 요청이 한꺼번에 몰리지 않게 한다.
- 전체 상세를 정상 조회한 뒤 링크가 실제로 빈 경우에만 ‘KOPIS에서 제공하는 예매처 링크가 없어요’라고 안내한다. 이는 실제 예매처 부재를 보장하는 문구가 아니다.
- 상세 페이지와 홈의 상세 조회 캐시는 `concert-detail` 키를 공유한다. 이전 `concert` 키에 저장된 요약 응답은 사용하지 않는다. 상세 화면 진입 시 재조회한다.
- 오류 화면에는 상세 조회 실패 안내와 다시 불러오기 버튼이 있다. 재조회 중에는 스켈레톤을 표시한다. 홈에서도 예매처 조회 실패/재시도를 구분한다.
- KOPIS 상세 실패 → 502 → 재시도 성공 시 예매처 복구, 시설 실패, 정상 응답의 실제 빈 링크, HTTP 오류 전달을 모의 서버 테스트로 검증한다.

외부 서비스 장애 자체를 제거하는 변경은 아니다. 서버 재시작 후 과거 공연 UUID는 검색 캐시를 통해 다시 식별해야 하는 기존 제약이 남아 있으며, 영구 KOPIS ID 매핑은 별도 작업이다.

# 로직·클라이언트 상태

- 날짜·검색·필터·지도·레이아웃 계산은 UI 없이 테스트 가능한 함수로 유지한다. Context/React hook은 기존 `*-state.tsx`, provider/hook 패턴을 따른다.
- API 타입은 기존 `api` 정의를 재사용한다. 순수 함수에서 fetch·스토리지·모델 호출을 숨겨 실행하지 않는다.
- 찜/내 일정 AsyncStorage 키와 저장 형식은 기존 데이터 호환성을 유지한다. 변경이 필요하면 읽기/마이그레이션을 고려한다.
- 굿즈 상태는 메모리 목업이다. 상태 enum·가격 숫자 정규화·사진 개수/용량/필수 검증을 공통 함수로 유지한다.
- 아티스트 별칭·한영 검색과 안정적인 ID 기반 중복 제거를 유지한다. 이름만으로 서로 다른 가수를 합치지 않는다.
- 시간 기반 함수는 가능한 한 `now`를 인자로 받아 테스트한다. 한국 달력 날짜와 UTC 문자열의 단순 자르기를 혼동하지 않는다.
- 지도 핀은 `hasVenueCoordinates`/`mapVenues` 검증을 통과해야 한다. 저장된 KOPIS 요약은 상세 갱신 전 좌표를 신뢰하지 않고, 갱신 실패를 찜 삭제로 처리하지 않는다.
- 현 위치는 권한을 받은 값만 메모리에서 사용한다. 요청 없이 정밀 좌표를 영속 저장·서버 전송·분석 로그에 넣지 않는다.
- `responsiveLayout`의 반올림/분수 픽셀 오차 방어를 유지한다. breakpoint 변경은 관련 화면과 `responsive.test.mjs`를 함께 확인한다.
- Analytics는 운영 웹 origin만 수집하고 관리자 화면·query/fragment·개인정보를 제외하는 기존 필터를 유지한다.
- 로직 변경 시 `mobile/tests`에 정상·경계·실패 회귀 테스트를 추가한다.

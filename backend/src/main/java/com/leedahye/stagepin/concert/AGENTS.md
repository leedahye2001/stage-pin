# 공연·KOPIS

- KOPIS ID와 응답 UUID의 기존 변환을 유지한다. 식별자 변경은 저장된 찜·일정 연결을 깨뜨릴 수 있다.
- 직접 KOPIS 상세 조회는 `PF[0-9]{1,12}` 형식을 외부 요청 전에 검사한다.
- 목록 응답의 지역은 공연장 좌표가 아니다. 좌표를 모르면 기존 `(0, 0)` 미확인 값으로 두고, 상세 공연/시설 조회로 확인한다. 지역 중심점을 실제 공연장 핀으로 쓰지 않는다.
- 과거 공연 검색·찜한 공연 조회를 예정 공연만 남기는 필터로 바꾸지 않는다. 완료/진행 중/예정/취소 처리는 클라이언트와 일치시킨다.
- 상세 조회 실패는 오류로 반환한다. 목록 요약을 상세 성공처럼 반환해 예매처가 없는 공연으로 오인시키지 않는다.
- 예매처는 확인된 `relates` 링크와 실제 URL로 분류한다. 제목으로 예매 URL을 조립하거나 KOPIS에서 선예매/일반예매 시작일을 제공한다고 가정하지 않는다.
- 현재 KOPIS 주소는 코드에 지정된 HTTP endpoint다. HTTPS 전환은 실제 호환성 확인 후 수행하고, `service` 키는 절대 로그에 노출하지 않는다.
- 목록/검색/상세의 캐시와 조회 제한을 유지한다. '최대한 수집'을 무제한 요청이나 무허가 예매처 스크래핑으로 구현하지 않는다.
- 분류·랭킹 변경은 `FanCategoryClassifierTest`, `HomeConcertRankerTest`, 상세 실패·좌표 변경은 `KopisConcertClientTest`, `KopisDetailFailureTest`로 검증한다.
